## 二、为什么从 BST 跳到「多路树」

### 2.1 BST 的问题（复习）

二叉搜索树按升序插入会退化成链，高度 `h = Θ(n)`。阶段 2 用旋转在**二叉**结构里把树拉扁；2-3 / 2-3-4 树换了一条路：

> **让每个节点能存多个键、有多个分支**，树天然更矮；变「满」时不往深处单边长，而是**分裂并把中间键上推**。

### 2.2 多路搜索树的核心直觉

```text
BST：每个节点最多 1 个键、2 个孩子 → 容易单边变深
2-3 树：每个节点 1～2 个键、2～3 个孩子 → 更扁，叶子同层
2-3-4 树：每个节点 1～3 个键、2～4 个孩子 → 更宽容，分裂逻辑统一
```

```mermaid
flowchart LR
    BST[BST 单边插入变链]
    Multi[多路树 满则分裂上推]
    Flat[高度 O log n 且稳定]
    BST -->|阶段3 换思路| Multi --> Flat
```

### 2.3 与红黑树的一句话关系

**红黑树不是新物种**：它是把 2-3-4 树的 3-节点、4-节点，用「黑色 2-节点 + 红色边粘合」画成二叉指针的样子。  
本阶段把 2-3-4 的逻辑学透，阶段 4 背 case 会少一半痛苦。

## 三、2-3 树

### 3.1 节点类型

2-3 树是**有序多路搜索树**，节点只分两类（有时把空树也算作特例）：

| 类型 | 键个数 | 子指针个数 | 示意 |
|------|--------|------------|------|
| **2-节点** | 1 | 2 | `[K]`，左子键均 < K，右子键均 > K |
| **3-节点** | 2 | 3 | `[K1 \| K2]`，左 < K1，中间 K1 < x < K2，右 > K2 |

```text
2-节点：                 3-节点：
    [K]                    [K1 | K2]
   /   \                 /    |    \
  <K    >K              <K1  K1~K2  >K2
```

**重要约定**（本系列与 Sedgewick / CLRS 的 B 树表述一致，后面不反复说）：

- 键在节点内**有序**：`K1 < K2`
- **内部节点与叶子都可以存键**：查找时在每一层都比较键；**新键只插入叶子**，叶满分裂后**中间键上推到父节点**（父节点因此也会有键，如 §3.5 的根 `[20]`）
- **叶子**：无子指针的节点；**内部节点**：有 2～3 个子指针，键用于划分子树
- **所有叶子在同一层**（完美平衡）

> **与 B+ 树的区别**：B+ 树只有叶子存「记录」，内部节点只做路由；本阶段的 2-3 / 2-3-4 树是 **B 树（m=4）** 模型，内外节点均可存键。学红黑树对应关系时，请按本约定理解。

```text
内部 2-节点 [20] 与叶子 2-节点 [10] 外形都是 [K]，
差别：前者下面挂着子树，后者没有孩子。
```

### 3.2 查找

从根出发，在**当前节点内**比较 1～2 个键，决定走哪条分支：

```text
在 2-节点 [K]：     key < K → 左；key > K → 右
在 3-节点 [K1|K2]： key < K1 → 最左；K1 < key < K2 → 中；key > K2 → 最右
```

与 BST 相同：每下一层排除一批键，路径长度 = 树高 = `O(log n)`。

**例**：在下列树中查找 `25`

```text
        [30]
       /    \
   [10|20]  [40]
   /  |  \    \
 [5][15][25] [50]
```

`25`：根 `30` → 左；`[10|20]` → `20 < 25` → 中间 → 命中叶子 `[25]`。

### 3.3 插入：先下落，满则分裂，中间键上推

2-3 树插入的固定流程：

```text
1. 查找下落，直到目标叶子（或空位）
2. 把新键插入叶子
3. 若叶子未满（2-节点变 3-节点）→ 结束
4. 若叶子已满（3-节点再插入）→ 分裂为两个 2-节点，中间键上推到父节点
5. 若上推导致父节点也满 → 继续分裂、继续上推（根分裂则树增高 1 层）
```

**分裂规则（3-节点 + 1 个新键 → 4 个键）**：

```text
满叶：[a | b | c]（临时 4 键，或理解为 3-节点塞不进）
      ↓ 分裂
左 2-节点 [a]  |  上推 b  |  右 2-节点 [c]
```

中间键 `b` **上推**到父节点；左右两半成为父的新相邻子树。

### 3.4 插入例题：依次插入 `10, 20`

| 步骤 | 操作 | 结果 |
|------|------|------|
| 插 `10` | 空树 → 叶子 2-节点 | `[10]` |
| 插 `20` | 同叶，2-节点变 3-节点 | `[10 \| 20]` |

无需分裂，根不变。

### 3.5 插入例题：再插入 `30`（触发分裂）

当前叶子 `[10 | 20]` 为 3-节点，插入 `30` 后临时为 `[10 | 20 | 30]`，必须分裂：

```text
分裂前（满叶）：[10 | 20 | 30]
分裂后：
        [20]          ← 中间键 20 上推为新根
       /    \
    [10]    [30]      ← 两个 2-节点叶子
```

- **发生分裂**：是  
- **根是否变化**：是（原根是叶子，上推后 `20` 成为新根，树高 +1）

这与大纲中 2-3-4 树过关题 `10, 20, 30` 的逻辑**完全一致**（见第七节）。

### 3.6 插入例题：在 §3.5 结果上插入 `5, 15`

起点为 §3.5 分裂后的树（根 `[20]`，左叶 `[10]`，右叶 `[30]`）：

```text
        [20]
       /    \
    [10]    [30]
```

**插 `5`**：`5 < 20` → 左子树；落入左叶 `[10]`，合并为 `[5 | 10]`。根仍为 `[20]`，无分裂。

```text
        [20]
       /    \
  [5 | 10]  [30]
```

**插 `15`**：`15 < 20` → 左子树；落入左叶 `[5 | 10 | 15]`（临时 3 键，满）→ **分裂**：

```text
左叶 [5]  |  上推 10  |  右叶 [15]
```

`10` 并入父节点 `[20]`，父由 2-节点变为 3-节点 `[10 | 20]`，三个孩子依次为 `[5]`、`[15]`、`[30]`：

```text
      [10 | 20]
      /    |    \
    [5]  [15]  [30]
```

- **插 `5`**：无分裂，仅左叶变宽  
- **插 `15`**：左叶分裂，**上推的是中间键 `10`（不是 `15`）**；根变为 3-节点，树高仍为 2  

可与仓库内 `TestAllModel/.../tree/TwoThreeTreeDemoTest` 对照运行结果。

### 3.7 高度与复杂度

| 性质 | 说明 |
|------|------|
| 叶子同层 | 任意时刻所有叶子深度相同 |
| 树高 | `h = O(log n)`，底数约为 2～3（每节点至少 2 路分支） |
| 查找 / 插入 | `O(log n)`；插入含分裂链，均摊仍为 `O(log n)` |

**对比 BST 链**：升序插入不会在单侧叠成长链，而是不断在叶层**变宽 → 分裂 → 上推**，高度增长极慢。

## 四、2-3-4 树

### 4.1 在 2-3 树上多加一种节点

2-3-4 树允许第三种内部/叶子形态：

| 类型       | 键个数   | 子指针个数 |
|----------|-------|-------|
| 2-节点     | 1     | 2     |
| 3-节点     | 2     | 3     |
| **4-节点** | **3** | **4** |

```text
4-节点：
      [K1 | K2 | K3]
     /    |    |    \
   <K1  K1~K2  K2~K3  >K3
```

其余性质与 2-3 树相同：有序、叶子同层、查找按节点内键选分支。

### 4.2 插入：与 2-3 树同一套分裂逻辑

```text
1. 查找到叶子并插入新键
2. 节点未满 → 结束（2→3，或 3→4）
3. 4-节点再插入（临时 5 键）→ 不可能；实际是 4-节点已满不能再直接插
   标准做法：4-节点先视为满，插入导致分裂
```

**满 4-节点分裂**（4 键 `a,b,c,d` 或 3 键 + 新键）：

```text
满：[a | b | c | d]  （按序 4 个键）
     ↓
左 2-节点 [a]  |  上推 b  |  右 2-节点 [c | d]  或  [c]、[d] 依实现均分
```

常见均分（4 键变两个 2-节点）：

```text
[a | b | c | d]  →  左 [a]  上推 b  右 [c | d]
```

中间键上推；若父也是 4-节点，则**连锁分裂**直到根或父有空间。

### 4.3 过关例题：空树插入 `10, 20, 30`

| 步骤 | 树形态 | 说明 |
|------|--------|------|
| 插 `10` | `[10]` | 2-节点叶子 |
| 插 `20` | `[10 \| 20]` | 2-节点 → 3-节点，无分裂 |
| 插 `30` | 根 `[20]`，子 `[10]`、`[30]` | 3-节点变满 → **分裂**；**中间键 20 上推为新根** |

```text
插 30 前：  [10 | 20 | 30]  （3-节点，再插 30 即满 4-键）

插 30 后：
        [20]
       /    \
    [10]    [30]
```

**答案摘要**：

1. **是否分裂**：第三次插入 `30` 时发生分裂。  
2. **根是否变化**：是，`20` 成为新根，树高从 1 增至 2。

### 4.4 插入例题：继续插入 `5, 15, 25, 40`

在 `20` 为根、`[10]`、`[30]` 为叶的基础上（与 §3.6 前半段相同）：

```text
插 5：  左叶 [5|10]，根仍 [20]

插 15： 左叶 [5|10|15] 满 → 分裂，中间键 10 上推到根
        根变 [10|20]，左子 [5]、中子 [15]、右子 [30]

      [10 | 20]
      /    |    \
    [5]  [15]  [30]

插 25： 落入右叶 [30] 侧，右叶变 [25|30]

插 40： 右叶 [25|30|40] 满 → 分裂，中间键 30 上推（若父已满则继续分裂）
```

纸笔练习时**逐步画、逐步检查叶子是否同层**即可；分裂时**永远上推有序中间键**，不必死记每一种终态形状。

### 4.5 为什么不会 BST 式链式退化？

用一句话回答大纲自测：

> **2-3-4 树不允许单边无限叠高**：节点最多装到 4-节点，再插入只能**分裂并把中间键上推**，增高发生在整条路径上的「变宽→裂开」，且**所有叶子始终同层**，高度保持在 `Θ(log n)`。

对比：

| | BST 升序插入 | 2-3-4 树升序插入 |
|---|-------------|------------------|
| 形态 | 右链 `1-2-3-…-n` | 反复叶层变宽、分裂、根上推 |
| 高度 | `Θ(n)` | `Θ(log n)` |
| 机制 | 每键多一层 | 每若干键触发一次分裂 |

### 4.6 与 BST 的对比小结

| 维度   | BST        | 2-3-4 树         |
|------|------------|-----------------|
| 分支因子 | 2          | 2～4             |
| 平衡手段 | 旋转（AVL/红黑） | 分裂 + 上推         |
| 最坏高度 | `O(n)`     | `O(log n)`      |
| 实现载体 | 天然二叉指针     | 教材多画多路；工程用红黑树模拟 |

## 五、2-3-4 树与 B 树的关系

### 5.1 B 树（阶数 m）在说什么

**B 树**是磁盘友好、多路平衡搜索树的统称：

- 每个节点最多 **m 个孩子**、**m−1 个键**
- 非根节点至少 **⌈m/2⌉−1 个键**（除根外不能太空）
- 所有叶子在同一层

### 5.2 2-3-4 树 = 阶数为 4 的 B 树

取 **m = 4**：

- 最多 3 个键、4 个孩子 → 正是 **4-节点**
- 非根至少 1 个键 → **2-节点**
- 中间状态 → **3-节点**

因此：

```text
2-3-4 树  ≡  B 树（m=4）在内存算法课里的名字
```

### 5.3 和数据库 B+ 树的距离

| 结构 | 典型用途 | 与本阶段关系 |
|------|----------|--------------|
| 2-3-4 / B 树 | 算法教材、红黑树理论模型 | **本阶段** |
| B+ 树 | InnoDB 索引、页分裂 | 叶子链表 + 键只复制品；**分裂/上推直觉相同** |
| 红黑树 | `TreeMap`、JDK 哈希树化 | **阶段 4**，等价实现 2-3-4 |

学 2-3-4 等于学了 **最小号的 B 树**；以后读 B+ 只需加「叶子串成链表、非叶只做路由」。

## 六、与红黑树的心理模型（预习阶段 4）

不必现在背五条性质，先建立**对应关系**，阶段 4 会展开。

### 6.1 把 3-节点、4-节点画成二叉

```text
2-3-4 的 2-节点 [K]     →  黑节点 K
2-3-4 的 3-节点 [K1|K2] →  黑 K1，红 K2 作为 K1 的右孩子（或左孩子，依约定）
2-3-4 的 4-节点          →  三个黑键用红边粘合的一种二叉形态
```

```text
3-节点 [10 | 20]  的一种红黑画法：

    10(黑)
      \
      20(红)
```

### 6.2 分裂 ↔ 变色 + 旋转

| 2-3-4 树    | 红黑树（直觉）            |
|------------|--------------------|
| 4-节点满，插入分裂 | 连续红或黑高失衡 → 变色 / 旋转 |
| 中间键上推      | 上推对应「父节点变色、继续向上修复」 |
| 根分裂增高      | 新根涂黑、树高 +1         |

**记住**：阶段 4 的 case 表，是在二叉指针上**模拟**本阶段的分裂与上推。

## 七、统一算法模板（插入）

```text
函数 插入(T, key):
    若 T 为空: 返回 单键叶子
    沿查找路径下降到叶子 L
    将 key 插入 L
    若 L 未超过容量: 返回
    否则:
        (L_left, mid, L_right) = 分裂(L)
        从 L 的父节点开始，将 mid 插入父节点
        若父满，重复分裂上推
        若一直推到原根之上: 新根 = mid，高 +1
```

2-3 树与 2-3-4 树的差别仅在「容量」：2-3 叶最多 2 键，2-3-4 叶最多 3 键；**分裂与上推手势相同**。

## 九、常见误区

| 误区 | 正解 |
|------|------|
| 「键只能出现在叶子」 | 本系列采用 **B 树模型**：内外都可存键；**只有插入操作**限定为先落叶子，上推后键会出现在内部节点 |
| 「4-节点有 4 个键」 | 4-节点是 **3 个键、4 个孩子** |
| 「分裂时上推新插入的键」 | 上推的是分裂后 **有序中间键**（如 `[5,10,15]` 上推 `10`，不是 `15`） |
| 「分裂随便砍一半」 | 必须取**有序中间键**上推，保证搜索性质 |
| 「2-3 树和红黑树无关」 | 红黑树是 2-3-4 的**等价二叉实现** |
| 「B 树和 2-3-4 是两套」 | 2-3-4 是 **B 树 m=4** 的特例 |
| 「Insertion 一定要预分裂」 | 教材有「自顶向下预分裂」变体；本阶段掌握**落叶后分裂**即可 |
