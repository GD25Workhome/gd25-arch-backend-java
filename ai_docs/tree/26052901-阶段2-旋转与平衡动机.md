## 二、为什么要「平衡」——BST 退化回顾

### 2.1 问题从哪来

阶段 1 已见过：按升序 `1, 2, 3, 4, 5` 依次插入 BST，会得到一条向右延伸的链：

```text
1
 \
  2
   \
    3
     \
      4
       \
        5
```

此时：

- **树高** `h = n`（`n` 为节点数）
- **查找 / 插入 / 删除** 都要从根沿唯一路径走到底，最坏 **O(n)**，和有序数组线性扫描没区别

理想情况是一棵「够扁」的树：高度约为 `⌊log₂ n⌋`，路径长度短，操作 **O(log n)**。

### 2.2 「平衡」在修什么

**平衡**不是要求左右子树节点数完全相等，而是：

> **控制树高**，使高度与 `log n` 同阶，从而保证增删查的路径长度可控。

```text
不平衡（链）          更平衡（近似满二叉）
h = O(n)              h = O(log n)
查找最坏 O(n)         查找最坏 O(log n)
```

### 2.3 与操作复杂度的关系

对 BST 而言，一次查找、插入、删除的代价 ≈ **从根到目标节点的路径长度** ≈ **树高**（或高度量级）。

| 树形态 | 高度 | 单次操作最坏 |
|--------|------|--------------|
| 退化成链 | `Θ(n)` | `Θ(n)` |
| 近似平衡 | `Θ(log n)` | `Θ(log n)` |

**结论**：平衡树的核心工程目标，是在插入、删除破坏形状后，用有限次局部调整把高度「拉回来」。  
**旋转**就是这类调整里最基础、也最常用的一种手势。

## 三、旋转是什么——只改形状，不改有序性

### 3.1 核心性质（务必记住）

1. **旋转是局部操作**：只涉及常数个指针（父、子、孙），不动整棵树。
2. **旋转后仍是 BST**：对任意节点，仍满足左子树键 < 根 < 右子树键。
3. **中序遍历结果不变**：这是判断「旋转画对了没有」的金标准。

第 3 点最重要：旋转**不会**打乱键的大小关系，只是把「谁当父、谁当子」换了个挂法，让树变矮或变匀称。

### 3.2 右旋（Right Rotation）

**适用直觉**：父节点在「左孩子的右边」形成向左倾斜的链（左链过重），或需要把左子树上提。

**结构变化**（以节点 `Y` 为旋转轴，`X` 是 `Y` 的左孩子）：

```text
旋转前：                 旋转后：
    Y                        X
   / \                      / \
  X   γ        右旋         α   Y
 / \          ======>          / \
α   β                          β   γ
```

**口诀**：

- `X` **上去**当新子树根（原 `Y` 的左孩子变根）
- `Y` **下去**当 `X` 的右孩子
- `β`（`X` 的右子树）挂到 `Y` 的**左边**（填补 `X` 右侧空位）

**中序验证**（键名即中序顺序）：

- 旋转前：`α` → `X` → `β` → `Y` → `γ`
- 旋转后：左子树 `α,X,β`，根 `X`，右子树 `Y` 的中序仍是 `β,Y,γ` → 整体仍是 `α,X,β,Y,γ`

### 3.3 左旋（Left Rotation）

**适用直觉**：父节点在「右孩子的左边」形成向右倾斜的链（右链过重）。

**结构变化**（以节点 `X` 为旋转轴，`Y` 是 `X` 的右孩子）：

```text
旋转前：                 旋转后：
  X                          Y
 / \                        / \
α   Y          左旋        X   γ
   / \        ======>      / \
  β   γ                  α   β
```

**口诀**：

- `Y` **上去**当新子树根
- `X` **下去**当 `Y` 的左孩子
- `β`（`Y` 的左子树）挂到 `X` 的**右边**

左旋与右旋互为镜像；记住一种，另一种左右对调即可。

### 3.4 指针层面在改什么（实现向，可选）

以右旋为例，逻辑上等价于：

```text
Y.left  = X
X.right = β   // 原 Y.left.right
β.parent = Y  // 若维护父指针
Y 成为 X 的右子
X 替代 Y 的位置（接父指针）
```

左旋同理，把 `left`/`right` 对调。  
面试或读 JDK 源码前，纸笔阶段**先会画图**即可。

## 四、完整例题：右斜链 `1 → 2 → 3` 做一次左旋

大纲过关题：**对链 `1-2-3`（右斜）左旋，并核对中序。**

### 4.1 旋转前

按 BST 插入 `1, 2, 3` 得到：

```text
    1
     \
      2
       \
        3
```

- 高度 `h = 3`
- 中序：`1, 2, 3`

### 4.2 在谁身上左旋？

对**最上层**的倾斜关系做旋：以 `1` 为轴，对其右孩子 `2` 做**左旋**（把右链拉平）。

```text
步骤：1 的右孩子是 2 → 左旋(1)

    1                2
     \              / \
      2     =>     1   3
       \
        3
```

### 4.3 旋转后检查

| 检查项 | 结果 |
|--------|------|
| BST 性质 | `1 < 2 < 3`，左子 `1`，右子 `3` ✓ |
| 中序 | 左 `1`，根 `2`，右 `3` → **`1, 2, 3`**，与旋转前相同 ✓ |
| 高度 | 从 `3` 降为 `2` ✓ |

一次左旋并没有把树变成「完美平衡」，但已经演示了：**同一组键，换一种挂法，高度可以变小，有序性不变**。

### 4.4 若继续插入 `4, 5` 会怎样（延伸直觉）

右斜链继续增长后，可在路径上多次左旋，或后续用 AVL/红黑树的规则组合双旋。  
本阶段只需建立「链太偏 → 旋转拉扁」的直觉，不必背完整修复表。

## 五、左斜链例题：对 `3 → 2 → 1` 做一次右旋

对称练习：按 `3, 2, 1` 插入 BST：

```text
旋转前：          右旋(3) 后：
  3                  2
 /                  / \
2                  1   3
/
1
```

- 旋转前中序：`1, 2, 3`
- 旋转后中序：左 `1`，根 `2`，右 `3` → **`1, 2, 3`** ✓

与右斜链左旋是同一套逻辑，方向相反。

## 六、旋转与 BST 的关系——先有序，再调形

可以把这个顺序记牢，后面读红黑树会轻松很多：

```mermaid
flowchart LR
    A[按 BST 规则插入/删除] --> B[可能变高、变斜]
    B --> C[旋转 / 变色 / 分裂等局部修复]
    C --> D[仍满足 BST 有序性]
    D --> E[高度回到 O log n 量级]
```

| 问题 | 回答 |
|------|------|
| 旋转会改变键的大小关系吗？ | **不会**，只调整父子连接 |
| 旋转后还能用中序得到升序吗？ | **能**，中序与旋转前一致 |
| 旋转等于重新排序吗？ | **不是**，没有移动键的「值」，只移动节点位置 |
| 平衡树还叫搜索树吗？ | **是**，红黑树、AVL 都是 BST + 额外不变量 |

## 七、和后面阶段的衔接（先建立预期）

| 阶段 | 旋转扮演的角色 |
|------|----------------|
| **AVL**（拓展） | 平衡因子越界 → 单旋或双旋（本阶段可不背 case 名） |
| **2-3-4 树** | 多路树用「分裂、上推」维持矮树；概念上对应「变高前先拆开」 |
| **红黑树** | 插入/删除时，uncle 黑则**旋转 + 变色**；与 2-3-4 节点分裂等价 |

你现在学的左旋/右旋，就是红黑树修复里出现的**同一手势**。  
先在这里画熟，阶段 4 看到 `zig-zig`、`zig-zag` 只是在说「连续两个节点在同侧还是异侧」，不必重新学一种新操作。

## 九、常见误区

| 误区 | 正解 |
|------|------|
| 「平衡 = 左右子树节点数相等」 | 只要求高度可控，不要求完美对称 |
| 「旋转会改变中序」 | 单旋/双旋的设计目标就是**保持中序** |
| 「左旋和右旋随便选一个」 | 要看倾斜方向：右链过重用左旋，左链过重用右旋 |
| 「学完旋转就等于会 AVL」 | AVL 还要算平衡因子、区分单旋/双旋；本阶段只练手势 |
| 「平衡树不用 BST 规则」 | 查找仍从根比较左右；平衡规则只在增删后修复形状 |
